# 模型：从「要不要预测」到「哪些数字能信」

## 一、当前结论（先看这个）

| 能做的 | 实测 |
|---|---|
| 剩余等待的中位数与区间 | 中位 0.8 天，80% 区间 0–4.6 天（随数据更新变化） |
| 分位数校准 | 说「50% 分位」时，历史实际命中 **50.0%**（目标 50%） |

| 做不到的 | 实测 |
|---|---|
| 判断「未来 7 天内会不会发生」 | Brier skill **≈ −2.3%**，即不如「忽略等待时长、直接按基准率猜」 |

**所以产品输出的是时间分位数，不是事件概率。** 概率条保留展示，但标注为未校准。

## 二、数据形态

- 51 个已完成间隔 + 1 个右删失间隔（当前未结束），跨度约 360 天。
- 间隔分布高度右偏：0–3 天占 35/52，长尾到 67.7 天。
- 第 11–13 天存在**零事件平台期**（活到 11 天的有 7 个，之后 3 天一个都没发生）。

## 三、模型

**分段常数风险模型**（piecewise-constant hazard）：

- 风险率 λ(d) 按已等待天数 d 分桶（默认断点 `0,1,2,3,5,8,14,30,∞`），桶内为常数。
- 每个桶内的率用 **Gamma-Poisson 收缩**（先验强度 `DEFAULT_PRIOR = 3`）向全局率收缩。
  **零事件桶必须收缩**，否则会输出「0%，绝不可能」这种断言。
- 时间衰减：可选半衰期（生产配置 45 天），让近期样本权重更高。
- 训练窗口：生产配置只用**最近 20 个间隔**。
- **右删失必须计入暴露量**：当前未结束的间隔只贡献暴露量、不贡献事件数。漏掉它会系统性低估风险率。

## 四、为什么不用 Brier 分数选参数

7 天窗口的基准发生率就有 80.8%——闭眼猜「会」也能拿到不难看的 Brier。
实测不同配置的 skill 长期在 ±10% 内正负翻转（全量等权 +7.22%，生产配置 −2.31%）。
**用 Brier 选型等于拟合噪声。**

改用**分位数覆盖率检验**：说「中位数 X 天」时，历史上是否真有一半落在 X 之内。
这个指标无法靠调参糊弄。

## 五、必须披露的偏差：节奏在加速

把全部历史间隔按时间等分三段：

| 阶段 | 平均间隔 | 最大 |
|---|---|---|
| 第 1 段 | **12.39 天** | 67.7 天 |
| 第 2 段 | **4.92 天** | 18.5 天 |
| 第 3 段 | **3.03 天** | 8.4 天 |

降幅 76%。两个极端长等待（49.7 / 67.7 天）**只出现在第一阶段**，
评估期（2026-03 起）最长只有 18.5 天 —— 这是全部分析偏差的根源。

后果：任何基于历史外推的模型都会**系统性高估**剩余等待时间。

## 六、样本外平移校准

用 walk-forward 回测的**样本外残差中位数**做平移（当前 −0.80 天）：

- 合法性来自「回测的每个预测点都只用该时刻**之前**的数据」，不属于拿答案对答案。
- 效果：`cov50` 从 70.0% → **50.0%**，`cov80` = 86.7%，近期中位偏差从 −2.65 天压到 −0.60 天。

## 七、外部信号一律不进模型（含 2026-10-04 的「28 天计划」）

模型只吃**一件事**：历史间隔序列。页面上那些「他说了什么」的外部信号 ——
`explicit` 预告、`hint` 线索、以及 2026-10-04 起新增的**每日重置窗口** ——
**一律不参与拟合、也不做约束**。

这不是疏漏，是刻意的。理由集中在一条：**模型的全部合法性来自「每个预测点只用该时刻
之前的数据」**（第六节那层平移校准之所以能算合法，就是靠这个）。往里面塞一个没有回测过的
外部先验，产出的数字就再也不能说自己是怎么来的了。

### 为什么「28 天计划」尤其不能喂进去

他的原话（2026-10-04）：

> `Over the next 28 days, each day we'll either ship one thing that is a clear improvement and relevant for most codex/work users or ship a full reset.`

| 可能的读法 | 成立吗 | 能不能进模型 |
|---|---|---|
| 「未来 28 天内**必定**发生一次重置」 | ❌ **不成立** —— 原文是 `either … or`，**二选一**，他完全可能 28 天全发改进 | 不能（前提就是错的） |
| 「这 28 天里**任何一天都可能**是重置日」 | ✅ 成立，但这是**定性**的：原文没有给出每日条件概率 | 不能（没有数字可入模） |

第二种读法看着「可以用」，其实一样不行：要把它变可用，得先估一个「某天他选中 reset
而不是 improvement」的概率 —— 而这个概率**我们没有观测**（28 天还没走完，样本 0）。
拿 `DEFAULT_PRIOR` 那种收缩先验硬凑一个数，等于编一个参数出来，
再让它去改「中位剩余等待」这种用户会当真的数字。**那正是本文件要防的事。**

> ⚠ 顺带纠一条**外部误读**：语料里有一条第三者转述写着
> `Wait what, Codex users get a free reset every day for 28 days if OpenAI doesn't ship a meaningful update?`
> —— 那是**别人的解读，不是原文**。原文没有「每天必有一次重置」的意思。
> 页面上因此写成「每天要么发一个改进、要么给一次完整重置 —— **期间任何一天都可能重置**」。

### 所以两者在页面上的关系是「并排，不相加」

「每日重置窗口」单独一块（`.sig-prog`，弱样式），「还要等多久」那块照旧只报历史外推的
中位与区间。**用户看到的两个数字互不修正** —— 这是有意的：它们的可信度来源不同，
一个来自「他说了什么」，一个来自「历史上多久来一次」，混在一起就谁也说不清。

代价是页面上会同时出现两个视角。接受这个代价，因为另一种做法（把窗口折进中位数）
会让那个中位数**无法被复核** —— 而复核能力是这个产品唯一的资产。

## 八、可复用到其它「事件何时再来」任务的方法论

1. 别用 Brier 选型 —— 先看基准发生率有多高。
2. 用分位数覆盖率检验校准，而不是用区分度。
3. 过程非平稳时，叠加一层样本外平移校准。
4. 参数选型用**近期表现**，不要用全期平均。
5. 右删失观测只计暴露、不计事件。
6. 零事件桶必须收缩。
7. 结论分层交付：哪些数字可信、哪些不可信，说清楚。
8. **外部信号只做展示，不进模型** —— 除非它带一个可回测的量化口径（见第七节）。

## 九、附录：免登录抓 X 推文

`x.com/<account>` 的未登录 HTML 内嵌 React Server Components 载荷，
键名**不带引号**，所以必须用正则，不能 `JSON.parse`：

```js
// 正文
/full_text:"((?:[^"\\]|\\.)*)"/g
// 推文 ID：client:VHdlZXQ6<base64>:  →  base64 解出 "Tweet:<id>"
/client:([A-Za-z0-9+/=]+):/g
// 时间戳
/created_at_ms:(\d{13})/g
```

- `cdn.syndication.twimg.com` 与 `syndication.twitter.com` 已不可用（返回 000），不要用。
- 历史回填走 `codex-resets.com/api/v1/resets?limit=100`，**limit 上限 100，传 200 返回 400**。
  回填记录一律标注 `attribution`。
- 复现全部回测数字：`node scripts/diagnose.mjs`。
