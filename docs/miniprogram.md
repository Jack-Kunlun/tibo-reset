# 小程序（微信）· 上手与截图终检

与网页端**共用同一套数据与模型代码**（`src/lib/`），差别只在渲染目标：
网页把 `scene.js` 的图元序列化成 SVG，小程序用 `utils/draw.js` 画到 canvas 2d。
几何只算一次，所以两端不会各画各的。

共用的**纯计算**模块由 `npm run build` 从 `src/lib/` 逐字同步到 `utils/`：
`scene.js`（图元几何）与 `outlook.js`（预测的**唯一结论对象** —— 预计时刻 / 置信度 /
依据摘要 / 依据卡②的三项判据与那句结语）。依据卡的判据**只读它**，两端都不照阈值再判一遍：
判据漂了，卡上那句「N 项未达标」就会说一件页面上并不成立的事。
**同步副本不要手改**。要加新模块，先确认它**自包含**（零 `import` 仓库内其它模块），
否则复制过去会在小程序里加载失败 —— 而 `build` 与 `test-*` 全绿（它们在 Node 里跑）。
详见 `AGENTS.md` 的「共享代码的同步规则」与 decisions.md 的 D-043。

## 一、目录

```

  app.json              三个原生 Tab 与暗色导航配色
  config.js             ★ 上线前要改的运行时配置（域名 / 开关 / 模板 ID）
  data/snapshot.js      ★ 构建产物：离线首屏数据快照，勿手改（**不入库**，见第二节第 2 步）
  utils/scene.js        ★ 构建产物：从 src/lib/scene.js 同步，勿手改
  utils/outlook.js      ★ 构建产物：从 src/lib/outlook.mjs 同步，勿手改
  utils/draw.js         图元 → canvas 2d（只负责「怎么画」，不做坐标计算）

  utils/share.js        分享标题 + 单页模式（朋友圈）适配，见 D-031
  utils/update.js       微信代码包更新：下载就绪提示、确认重启与失败反馈
  pages/index/          观测台首页（含 F9 提醒入口）
  pages/history/        月日历、日期明细与全部重置历史
  pages/analysis/       依据概要、真实间隔柱图与三组详细分析
  utils/dashboard.js   三页共享加载、格式化、刷新与生命周期
  styles/design.wxss   确认设计稿对应的版式与配色
```

三个 Tab 的职责：

- **观测**：有效线索置顶，日期预测、预告与落地提醒、等待时长和 Tibo 28 天计划。
- **记录**：UTC 月日历，点选日期看北京时刻的公告明细；历史行可展开原文并复制来源。
- **分析**：依据概要和最近 12 次间隔柱图；三个分组按需展开，保留概率、回测、节奏、历史图和样本披露。

三页按确认的三 Tab 设计稿还原，数据取实际视图模型。底部导航由微信原生 tabBar 提供。

28 天计划按原帖中的 Day 编号展示每天的功能更新、重置与补充动态；子编号和跨日补发
保留在原编号下。点选一天可读中文摘要、展开原文并复制来源。最新 Day 表示已采到的
最新编号，不等于已完成天数；空缺日只标「未见公告」，后续编号标「待更新」。
中文摘要与已采原文全文绑定，原帖变化或新帖尚未整理时回退原文摘要，不自动断言功能已交付。
历史跟进确认的展示关联同样绑定双方原文，且必须仍有确认记录才显示到账；不以发布时间接近
推断关联，也不改确认记录、预测或通知事件。UTC 月日历继续按实际确认日期展示。

服务端输出 `signals.calendar.plan`。旧服务缺少该字段时，同账号客户端可用包内计划快照，
并标注快照来源与成功采集时刻；显式 `plan: null`、`calendar: null` 或账号不匹配时不回填。

微信开发者工具的**项目根**有两种可用选法，本机现用的是第二种：

| 项目根 | `appid` 在哪 | 备注 |
|---|---|---|
| 仓库根 | `project.config.json`（入库，值为 `touristappid` 占位） | 已声明 `miniprogramRoot: "miniprogram/"`，能跑；占位 appid 不能上传，须先换成自己的 |
| `miniprogram/` | `miniprogram/project.config.json`（**不入库**，见 `.gitignore`，内含真实 appid） | 本机开发者工具实际打开的根（日志实证），09-23 那次上传也是在这个根下做的 |

⚠ **`appid` 与「编译模式」都存在各自根的 `project.config.json` 里**，换根时不会跟着走 ——
第七节第 16 条那个 `1154` 编译模式，要建在**你实际用的那个根**下。

## 二、上手（四步）

1. 导入项目根（见第一节末的两种选法），确认 `appid` 是你自己的
   —— 仓库根那份是占位值 `touristappid`，用它无法上传。
2. 生成构建产物。⚠ **快照不入库**（D-027），全新克隆必须先跑一次，否则小程序加载不了页面
   —— `miniprogram/utils/api.js` 在模块顶层 import 它。两条路径按需选：
   - `node scripts/build-snapshot.mjs` —— **只**写 `miniprogram/data/snapshot.js`（离线首屏数据）。
     `npm test` 的 `pretest` 会自动跑它，所以只跑测试的话不用手动执行。
   - `npm run build` —— 额外产出兜底页面 + OG 卡，并把 `src/lib/scene.js` 与
     `src/lib/outlook.mjs` 同步到 `miniprogram/utils/`（**不要手改那两个副本**）。
3. 改 `miniprogram/config.js`：`apiBase` 填实际域名、`enabled` 置 `true`。
4. 配微信后台的 `request` 合法域名（见第五节）。

## 三、为什么首屏不会白屏

数据有两个来源，页面**先出图再联网**：

| 来源 | 何时用 | 说明 |
|---|---|---|
| `data/snapshot.js` | 打开即用 | 构建期写死的快照（**不入库**，需先生成，见第二节第 2 步），离线也可用。冷启动永远是完整的 |
| `GET /api/state` | 联网且 `enabled: true` | 拿到后覆盖快照；本地缓存 30 分钟，超时不再当新鲜数据用 |

`enabled` 默认 `false`，这是有意的：`request` 合法域名没配之前，微信会让所有请求
走 `fail` 回调 —— **静默失败，不弹错**，比白屏更难查。所以在域名配好之前不要打开它。

> 本地调试想连本机服务？把 `apiBase` 指向 `http://127.0.0.1:8787`，
> 并在开发者工具「详情 → 本地设置」里勾上**不校验合法域名**。
> 这只是本地开关，与 `project.config.json` 的 `urlCheck` 无关，也不会跟着上传。

## 四、重置通知

主卡下方提供「重置预告」和「重置落地」两类选择，默认均选中。点击统一开启按钮时，
用一次 `wx.requestSubscribeMessage` 申请两个不同标题的模板，再按各模板返回的结果独立登记。
默认选中只表示本次申请的选择，不代表已获微信授权。进入页面、切换 Tab 和刷新只查询状态，
不会申请授权。服务端每次登记用新登录 code 换取 openid；客户端不接触 openid。
拒绝或授权接口失败不会显示已开启。
每类一次授权只能收到一次通知，推完后需重新开启。两类独立登记、独立消耗，预告不会消耗落地通知。重复点击已开启按钮不会叠加授权。

两类模板映射在 `server/subscribe-template.json`，微信后台的模板标题必须不同：

| 类型 / 模板 | 字段 | 内容 |
|---|---|---|
| 预告 / 信息发布提醒 | 发布标题 `thing12` | 重置预告，注明尚未确认落地 |
| 同上 | 信息类型 `thing3` | 重置预告 |
| 同上 | 信息来源 `thing4` | Tibo |
| 同上 | 发布时间 `time8` | 原始预告发布的北京时间 |
| 落地 / 服务进度通知 | 业务标题 `thing13` | 重置已落地，公开完成公告已确认 |
| 同上 | 更新时间 `time10` | 首次确认公告的北京时间 |
| 同上 | 温馨提示 `thing5` | 查看观测台了解详情 |

服务端配置 `WX_APPID` / `WX_SECRET` 后，通过公开配置接口下发可用模板 ID，客户端的
`subscribeTemplateId` 是保留的历史字段，当前不读取。入口只接受服务端确认可用的模板。
配置接口保留旧 `templateId`（落地模板），新增 `templateIds` 按类型提供模板。新客户端遇到
旧服务的单模板配置时保留原来的逐项授权入口，不把一个模板的同意结果登记成两份授权。
旧预告模板的待同步授权不能转用新模板，用户需重新授权；既有落地授权保持原模板处理。
普通页面始终保留通知状态；服务未就绪显示未开放，配置失败显示重试，均不申请授权。
朋友圈单页隐藏入口，不执行登录或授权。失败不会阻断观测页面。

回到首页或下拉刷新时查询服务端状态，推送消耗后恢复开启按钮；查询失败显示重试查询，
不猜测用户已开启。授权成功但登记失败显示「重试同步通知」，此时不再次拉起微信授权。

预告通知只在发现新的明确重置预告时发送，并说明尚未确认落地；模型概率、线索和每日窗口不触发通知。
落地通知只在确认新的重置记录后发送，确认的是公开完成公告，不代表核验了每位用户的个人账户到账。
临时发送失败在下一轮成功 ingest 时补推，两类分别去重；旧版服务端未支持预告通知时显示未就绪。
新模板需要后端更新后才会由配置接口提供；统一授权入口也需要小程序包更新。
退订会停止后续派发；已进入发送阶段的在途消息可能仍送达，当前链路不保证撤回。
开发者工具截图和接口打桩不能证明真实收信；真机验收需要分别确认授权、登记、通知接收和点击跳回首页。

第 9 条需要在真机检查；代码包跨版本切换另见第九节。

「代码接上了没有」（第 13 节测试），**验不到宿主里的真实表现**。第 16 条不必真的发朋友圈：
开发者工具「编译模式 → 添加编译模式 → 场景值填 1154」即可模拟。

## 八、视觉动效

页面有四组常驻动效，全部是纯 WXSS（`@keyframes` + `transform` / `opacity`），
没有用 `wx.createAnimation`，也没有引入任何组件库：

| 动效 | 位置 | 作用 |
|---|---|---|
| `rise` | 首屏各区块，按 0.02–0.32s 依次浮现 | 让静止的首屏有「依次到位」的顺序感 |
| `halo` | 信号横幅左上角光斑 + 徽章活点 | 让「有信号」这件事持续可见 |
| `breathe` | 等待偏久时的判定胶囊 | 把结论持续推到眼前。常规区间**不**呼吸 —— 一直闪就成了噪音 |
| `grow` | 等待进度尺的填充条 | 从 0 长出来，比直接显示一个静态百分比更有「时间在走」的意味 |

⚠ **全部依赖 CSS 动画。** 若某个机型不执行动画，`animation-fill-mode: both`
会让元素停在起始态（`opacity: 0`，即不可见）。终检第 9 条的真机检查必须覆盖这一项。

设计上刻意**没有**换成深色底或加高饱和色块 —— 那会和整站的水墨宣纸基调打架。
「不素」是靠**晕染、大字、动效**做出来的，不是靠换配色。

## 九、小程序更新提示

App 启动时注册一次微信 `UpdateManager`，微信负责检查与下载更新。收到
`onUpdateReady` 后才显示「更新已就绪」：选择「立即重启」会调用 `applyUpdate()`，
由微信重启并应用新代码包；「稍后」继续当前页面，同一运行实例不再重复提醒该更新。
后台收到下载完成通知会等回到前台再提示；前后台切换与重复初始化不叠加提示，朋友圈单页不弹重启提示。
下载失败只提示检查网络、稍后重新打开，不自动重启、不清缓存、不要求删除小程序。
宿主不支持更新接口时继续正常显示页面。失败监听注册异常不影响已注册的就绪监听；
旧弹窗跨越一次前后台切换后关闭，不补发同一条就绪提示。弹窗实际显示失败时允许下次进入重试。

本机验证分两层：

1. `npm run test:update` 验证宿主回调与确认流程；`node scripts/test-miniprogram.mjs`
   同时验证 App 的启动、前后台与单页模式接线。
2. 微信开发者工具的编译设置开启「下次编译模拟更新」，分别模拟成功与失败。
   成功时点「稍后」确认页面继续可用，再返回前台点「立即重启」；失败时只出现失败说明。
   模拟通过仍不能代替正式版跨版本验收：需要先安装带本功能的正式版，再发布后续版本，
   在 iOS、安卓验证实际下载、提示和重启。当前设备上运行的不带此逻辑的旧包，无法被此改动追溯添加提示。

接口语义依据[微信官方 API 声明](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)
与 [UpdateManager 文档](https://developers.weixin.qq.com/miniprogram/dev/api/base/update/UpdateManager.html)。
